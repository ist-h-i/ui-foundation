# ui-foundation

[English](README.md)

動作を実装したAngularのUI部品と、設定ファイルで見た目を調整できる仕組みを提供するnpmパッケージです。フォーム、表、ナビゲーション、ダイアログなどの部品を組み合わせて、アプリの画面を作れます。

色・文字・余白・寸法・角丸などを一つのYAMLで定義し、UI部品、Tailwindテーマ、AIの開発指針、検査設定へまとめて反映できます。

## できること

- **部品を組み合わせて画面を作る**：入力、選択、開閉、キーボード操作、処理中・エラーなどの表示や操作を備えたAngular部品を使えます。表示だけのモックではなく、アプリの状態やイベントにつないで利用する部品です。
- **アプリに合う見た目へ調整する**：色だけでなく文字、余白、形状、部品の寸法などを設定できます。Angular部品とTailwindのユーティリティが同じ設定を参照します。
- **生成と更新をまとめて行う**：CLIの`init`で設定のひな形を作り、`sync`で部品・スタイル・プロジェクト用Skill・検査器を一括生成します。変更前には`sync --dry-run`で差分を確認できます。
- **設計と実装のずれを確認する**：`check`で設定と生成物の不一致を調べ、指定したアプリソースのデザインルール逸脱を静的に検査できます。
- **AIにも設計の意図を渡す**：利用目的、制約、画面設計の指針、採用した設定をプロジェクト用Skillへ反映し、AIが画面を実装するときの判断材料にできます。

| 用途 | 代表的な部品 |

## 設定で変えられること

具体値を定義する「プリミティブ」と、その値をどこで使うかを定義する「セマンティック」を分けています。「プロファイル」は、この対応関係を名前付きでまとめた設定集です。独自の値とプロファイルを定義でき、決まったテーマから選ぶ方式には限定されません。

設定例の`guided`と`dense`は、同じ画面・部品へ異なる設定を適用するためのサンプルです。機能が組み込まれた特別な名前ではありません。

| 設定例の違い | `guided` | `dense` |
| --- | --- | --- |
| 主操作色 | 青 | 緑 |
| 本文サイズ | 1.125rem | 1rem |
| ページ余白 | 32px | 16px |
| 操作部品の角丸 | 12px | 4px |

`guided`を選ぶだけで画面が手順型になる、といった自動変換は行いません。画面構成や操作経路は、開発者やAIがアプリの目的に合わせて実装します。サンプル画面の「表示設定」は生成済みの設定を比較するもので、選択をYAMLへ保存する機能ではありません。実際のアプリでは一つのプロファイルに固定することもできます。

## 提供範囲

npmパッケージはCLIと生成元を配布し、利用先へAngularのTypeScriptソース、CSS、プロジェクト用Skill、検査器を生成します。コンパイル済みのAngularライブラリを直接importする方式ではなく、生成した部品を利用アプリでビルドします。Angularや描画エンジンなどの依存は[usageの依存関係](docs/ui-library-consumer-guide.ja.md#依存関係)に従って導入します。

| ui-foundationが提供するもの | 利用アプリが組み込むもの |
| --- | --- |
| UI部品の表示・操作・状態とイベント | 画面構成、業務ロジック、HTTP通信、保存・送信・Undo |
| ナビゲーションやリンクのUI | Angular Routerのルート定義・画面切替・遷移制御。既存部品とのRouter合成は未検証 |
| 設定からの生成と静的検査 | アプリのビルド、実操作・アクセシビリティ・見た目・使いやすさの確認 |

実行時のLLM API、サーバー、DBは提供しません。専門部品のworker、補助資産、外部サービスの認証や配信設定は利用アプリが用意します。静的検査の成功を、UX全体や任意の実行時挙動の保証とは扱いません。

## 言語の選択

README、利用ガイド、設計・API資料は日英で用意します。AI向けの入口は英語の `.agents/skills/project-ui/SKILL.md` です。同期後に、隣にある `project-context.md` と設定YAMLも参照します。

`init` は `default_language: en`、`init --language ja` は `default_language: ja` を保存します。この項目のない既存設定は日本語の既定値を引き継ぎます。実行中に言語を切り替えるときは、アプリの言語を `provideUiLocale` に渡します。部品の定型文言は安定IDと名前付き引数で指定し、業務ラベル・本文・APIエラーはアプリが翻訳します。[外部翻訳との接続と切り替え](docs/ui-library-consumer-guide.ja.md#locale文言rtl-の責任) · [beta.4からの移行](docs/ui-message-migration.ja.md)

## 使い始める

Angular アプリのルートで `0.2.0` を導入します。設定の初期化、部品の生成、依存関係の設定は導入ガイドに従ってください。 [導入ガイド](docs/ui-library-consumer-guide.ja.md)

```sh
npm install --save-dev --save-exact @hiroshi.inoue/ui-foundation@0.2.0
```

`0.2.0` の検証環境は Node.js 24.19.0、macOS arm64、Angular/CDK 22.3.0、TypeScript 6.0.3 です。対応範囲と更新・復旧の手順は利用契約を参照してください。 [利用契約](docs/npm-beta-readiness.ja.md)

## 生成物をGitで管理する場合

生成物をコミットする場合は、チェックアウト後もバイト列が変わらないようにします。初回の `git add` より前に、利用アプリのルートの `.gitattributes` へ以下を追加してください。全体に適用する `* text=auto` などの指定より後に記載します。

```gitattributes
.ui/generated/** -text
.agents/skills/project-ui/** -text
```

生成先を変更している場合は、`.ui/generated` を設定したパスに置き換えます。属性ファイルもコミットし、より後の指定や下位ディレクトリの属性で改行変換が再び有効にならないことを確認してください。特に `CHECKER-NOTICE.txt` には改行形式が混在する第三者ライセンスの原文が含まれることがあります。所有権のmanifestは生成物のバイト列からハッシュを計算します。

すでにGitで改行が変換されている場合は、まず復旧点を保存します。変換前の検証済みコピーから復元するか、従来の固定パッケージ版と設定を別ディレクトリで使って再生成します。復元対象のSHA-256が既存manifestに記録された値と一致することを確かめ、対象ファイルだけを置き換えます。手編集を許容するためにmanifestのハッシュを書き換えてはいけません。属性と復元したファイルをステージし、差分を確認してから、新規チェックアウトで `sync --dry-run` と `check` を実行します。元のバイト列を確認できない場合は、上書きせず所有権の競合を解消してください。
