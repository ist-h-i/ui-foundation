# 実装・検証計画

## 設定と解決

`src/config.ts`でYAMLの構造と型を検証し、`src/roles.ts`の役割契約へ接続する。必須役割、参照先、型、default_profile、色ペアを各プロファイルで確かめる。context/guidanceだけを変更しても見た目の値を推測しない。未知項目や旧preset/density設定は受理しない。

`src/tokens.ts`はプリミティブと解決済み意味トークン、全プロファイルのスコープ、Tailwindのテーマ接続を決定的に生成する。基底だけでなく各プロファイルのすべての対応関係を出力し、入れ子による意図しない継承を検査する。

## 生成とAIへの接続

`src/sync.ts`と`src/cli.ts`でinit/sync/checkを提供する。tokens.css、tailwind.css、Angular部品、Skillとproject-context、profile選択情報、policy/resolved、manifestを同じ解決結果から作る。

生成試験は冪等性、dry-run、文脈/対応変更の反映、未同期、手編集、未所有ファイル、欠損、manifest、symlink、プロジェクト外パス、initの保全、CLIの失敗終了を確認する。通常の書き込みエラーでは元の状態へ復元するが、プロセス強制終了への原子性を保証しない。

## UIの接続と比較

fixtureは生成した部品をコンパイルし、Tailwind CLIでCSSを作る。guided/denseを明示的に切り替え、同じ部品と同じ意味のユーティリティで色・文字・余白・角丸が変わることを計算済みスタイルで観測する。異なるプロファイルが入れ子になった場合も確認する。

| 観点 | 観測する結果 |
| --- | --- |
| 切替 | 画面を作り直さず入力・取得・実行状態を保つ。 |
| 非同期処理 | 処理中の再操作を抑止し、結果不明を偽らない。 |
| 部分障害 | 正常領域と入力が残り、局所再試行に接続できる。 |
| 入力と復旧 | エラー箇所が分かり、修正や実際のローカルデータのUndoによって継続できる。 |
| 操作 | ネイティブ要素の意味、キーボード操作、フォーカス、選択、dialog、hiddenを保つ。 |
| 表示 | 狭い画面・文字拡大・動き低減で情報と操作を維持する。 |
| 自動アクセシビリティ | 両プロファイルの対象状態をaxeで検査する。 |

明るい主操作背景とink文字の設定を解決・生成し、通常／現在地／hoverのリンクと選択中タブを実際のAngular部品で描画する。リンクのsurface／background、選択タブのsurfaceの文字色ペアを確認する。ナビゲーションとパンくずでは、320px幅、文字サイズ100%／200%、日本語／連続英字の全文が枠内に収まり、ページ全体の横スクロールが出ないことを測定し、フォーカス・href・現在地を確認する。

静止画は描画の証拠、操作試験は対象シナリオの証拠。どちらも利用者の理解や実業務の有効性を証明しない。

全181要求は`docs/ui-library-matrix.json`の原文制御項目を保ち、各カテゴリの実装・正式fixture・型付きprojection・純モデル・実操作の対応を記録する。後続のTree/Scheduler/編集表/media/specialist/Foundationは、旧部品への回帰と同じ生成物で検証する。実workerのimport/ready/計算/終了、PDFのページ、地図canvas、符号化画像の解読、vendor editorのnative入力を観測し、代替の表だけを根拠に、レンダラーが完成したとは扱わない。

生成後は独立した利用アプリで、公開barrelだけを入口とするstrict AOTを実行し、別の計算workerのエントリーポイントもコンパイルする。nullable CVAと不正型のnegative compile、HTTPで配信したアセットのバイト列/MIMEタイプ、新旧リクエストやフォーカスの転送、320px/文字200%/RTL/両プロファイルを対象にする。ライセンス原文・font source kitの保持を配布アセットとして確認する。

## 実行とレビュー

設定・生成元を変更したら`npm run ui:sync`で同期する。通常の`npm test`は、`ui:check:warnings`による設定・生成一致・静的検査と台帳照合、型検査、設定・生成・静的検査・純モデル・UI操作・SVG実描画の回帰を実行する。検証ツール自体は`npm run test:verification`、重点操作の複数エンジンでの検証は`npm run test:cross-browser`、仮想化したradioの追加回帰は`npm run test:ui:radio:cross-browser`で確認する。`npm run build`も生成物の未同期を拒否する。試験の成功は、実行した対象・条件・ソースのハッシュと結び付けて記録する。

実装後は正確なbase/headと実際のdiffを、実装過程の会話を引き継がない独立レビュー担当へ渡す。未コミット変更を含む場合は対象ファイルとハッシュを固定する。主担当が指摘をソース・試験・実行結果で確認し、重要な追加修正は別の新しいレビュー担当で再確認する。指定ソースのAST検査や対象を限定した複数エンジンでの試験が成功しても、Skillの自動選択、任意の実行時処理やCSSの供給、実スクリーンリーダー、実サービスの復元、実利用での有効性まで確認済みとは扱わない。

今回のユーザー指示はcommit・push・通常mergeまでを含む。実装、必要なローカル検証、正確な候補SHAの独立レビューを終え、リポジトリ・取り込み先・現在のhead・関連checkを確認してから主担当が公開操作を行う。PR上でもレビュー対象headとcheckを確認し、通常のmerge条件に従う。途中の段階完了やCIだけで全要求完了に変更しない。npm公開や本番deployは含めない。

## 指定ソースの静的検査

任意の`checks`を正本YAMLへ置き、全トークン用途と未承認Angular部品・ディレクティブを検査する。同梱`check-ui.cjs`はNodeで単独実行でき、CLIの生成一致検査と同じソース検査を使う。確定した違反は失敗、動的な処理など静的に確認できない箇所は警告、理由付き例外は別一覧へ記録する。設定・対象・例外・配布境界は[静的検査](static-checks.ja.md)を正本とする。

`test:static`は全用途の負例/許可例、省略形・関数・utility、Angular metadata/binding/DOM操作、外部部品の参照同一性、例外の適用件数、パス境界、別リポジトリの単独CLI終了状態を検証する。生成の冪等性、NOTICE/検査器の所有範囲、output移行は生成回帰で確認する。実操作・視覚・利用者理解の検証とは区別する。

本リポジトリの全警告は`docs/ui-warning-reviews.json`に一対一で分類し、理由、警告の発生元、対象を限定した回帰試験、Unknownとする範囲、再確認条件、根拠のアンカー/ハッシュを記録する。`ui:check:warnings`は`checkProject`の元診断を変更せずに照合し、未分類・消滅・重複・理由不足・台帳不備・根拠変更を失敗にする。エラーは台帳で承認できない。通常のtestに含めるが、利用アプリのYAMLや同梱CLIの警告終了状態は変更しない。正負回帰は`tests/static/warning-review.test.ts`へ置く。

取り込み対象、全件分類と今回の検証・独立レビュー・公開結果は[固定した検証記録](verification/ui-static-warning-release-20261018/README.md)へまとめる。試験に必要な過去の固定入力は`tests/fixtures/static-checks/`へ置き、巨大なローカルトレースや一時チェックアウトをテストの依存にしない。古い件数・試験結果を現在の対象の証拠として流用せず、未実行と未確認を残す。
