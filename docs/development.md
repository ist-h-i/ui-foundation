# 開発方針

## 進め方

要件原文を保存し、設計変更は理由と責任境界を明示します。一つの観測可能な段階で実装し、機能を広げる前に適合・不適合・衝突・判定不能の例を確認します。生成物を直接手直しせず、設定・テンプレート・規則を直します。

設定を提案するAIと、承認済み設定を実行するソフトウェアを分けます。全画面を画一化せず、必要情報、状態の意味、復旧と完了までの経路を共通化します。新しい部品を採用する前に、HTML標準要素や既存部品で足りるか確認します。

## 依存と公開

初期化段階では依存を追加しません。Angular、TypeScript、YAML解析、テンプレート／CSS解析、Playwrightなどは、それぞれの実装段階で対応版・保守性・導入量を確認して選び、lockfileと適切な試験を追加します。AI API、サーバー、DBを導入しません。

npmパッケージは `private: true` です。名称は仮称で、scopeや名前を予約しません。権利者による判断前にLICENSEや第三者への権利許諾を追加しません。

## 検証と記録

現在は文書と初期構成のみです。未実装のCLIを通ったことにしたり、npm testを成功するだけのコマンドへ置き換えたりしません。実装後は静的検査、実ブラウザー操作、AI・人によるレビューの対象と証拠を区別します。実際に実行した確認だけを報告します。

使用率や要素数をUXの総合品質に置き換えません。例外・未分類・未知の動的実装を結果に残し、適用範囲外や正当な計算を誤って禁止しないことも検証します。

## ファイルとGit

このプロジェクトの要件・新規ファイルだけを管理します。無関係の個人ファイル、認証情報、他プロジェクトのログや実測証拠をコピーしません。Gitの追跡対象と差分を確認し、小さな関連単位でcommitします。

利用アプリへのinit／syncでは所有範囲を明示し、dry-runと手編集検出を実装します。既存AGENTS.md／package.jsonの管理外部分、機能コード、個別拡張と試験を保全します。失敗や衝突を隠して上書きしません。
