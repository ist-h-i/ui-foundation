# 0006　生成UIの状態と外部入出力の境界

2026年11月20日採用。対象は各アプリにコピーされるAngularソース。

基本フォームを使うために、PDFや地図のエンジンまで導入する必要があった。また、読み込み先やコピー対象を変更した後に旧操作が完了するケースがある。どちらも依存先と処理の寿命を明示する必要がある。

- 行・選択・入力値などの `*-model.ts` はAngularから独立させる。部品はモデルを呼び出し、画面の入力・選択・表示をsignalsに接続する。検査はモデルが参照するローカルモジュールもたどる。外部依存はJSON解析の `jsonc-parser` と日付計算の `temporal-polyfill` に限り、追加や更新時にはフレームワークへの依存を再確認する。
- `core` は基本操作とネイティブ入力、`forms` はテキスト入力、`index` は全カタログの利用先を受け持つ。公開入口は同じ実装を再公開する。フォームと翻訳を使う配布試験は、専門エンジンを導入していないアプリで行う。
- PDFの読取では、部品が選択中の文書からResourceを駆動する。PDFアダプターが文書を開き、workerと描画セッションを解放する。再試行・切替・破棄時の表示と解放を実workerとブラウザーで確認する。
- コピーは利用者の操作から1回だけ開始し、対象を変更した後の通知を抑止する。保存やUndoは利用アプリが永続化を確認する。既存のAngular FormsとCDKは、それぞれの公開契約で接続する。

新しい描画エンジン、永続化を伴う操作、または軽量入口への依存追加を提案するときに、この境界と配布試験を再確認する。[仮想行の設計](0003-virtual-native-tab.md)・[Angularの非同期読取](https://angular.dev/guide/signals/resource)
