# プロジェクト要件

## 目指すこと

最初に設定するYAMLから、利用者やペルソナに応じてUIデザインを柔軟に変えられる開発基盤を作る。PR #1の未マージの初版はこの構造へ置き換え、旧方式への後方互換や二方式の併存を作らない。

具体値を置くプリミティブと、用途を表すセマンティックの二段階を設定に持つ。プロファイルごとの対応切替で色、余白、書体、文字サイズ、形状、操作寸法を制御する。Angular部品とTailwindは同じ対応を参照する。

## 段階

1. 利用者の目的・利用頻度・経験・端末・制約を判断材料として設定する。
2. AIがプリミティブの体系、意味トークンとの対応、プロファイルを提案する。既存パレットの選択だけでなく新しい体系も作れる。
3. 人が採用したYAMLを、通常のプログラムで検証・解決してUI部品、スタイル、Skill、検査設定へ同時反映する。
4. AIがプロファイルのguidanceと機能の目的を読み、画面構成と操作経路を実装する。
5. 設定/生成一致、実操作、意味/視覚を別々に検証する。

## 守る意味

共通化するのは特定の美学や全画面のレイアウトではなく、状態・操作・失敗・復旧の意味。必要な比較情報を維持し、色だけに依存しない。focus、選択、無効、処理中を混同しない。部分障害では正常な領域と入力を保ち、欠損と影響を伝える。

実データのUndo、処理取消、二重更新防止、安全に継続できる範囲は利用アプリが保証する。応答未取得を成功や失敗に決めつけない。年齢や役割のラベルだけから見た目を自動的に推定しない。

## 初版の範囲

単一リポジトリ、単一private npmパッケージ、Angular/TypeScript、Tailwind v4、YAML設定、init/sync/check、プロファイル例、生成Skill、実ブラウザー検証。実行時のAI API、サーバー、DB、全画面YAML DSL、複数フレームワーク、UX総合点、npm公開は含めない。

設定の型と必須役割、生成物の所有範囲、具体的な受入条件は[設計](design.md)に置く。
