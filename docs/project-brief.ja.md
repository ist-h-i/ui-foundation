# プロジェクト要件

## 目指すこと

最初に設定するYAMLから、利用者やペルソナに応じてUIデザインを柔軟に変えられる開発基盤を作る。二段階トークンとプロファイルを初版の構造とし、旧方式への後方互換は設けず、二つの方式を併存させない。

具体値を置くプリミティブと、用途を表すセマンティックの二段階を設定に持つ。プロファイルごとに対応関係を切り替え、色、余白、書体、文字サイズ、形状、操作領域の寸法を制御する。Angular部品とTailwindは同じ対応を参照する。

## 段階

1. 利用者の目的・利用頻度・経験・端末・制約を判断材料として設定する。
2. AIがプリミティブの体系、意味トークンとの対応、プロファイルを提案する。既存パレットの選択だけでなく新しい体系も作れる。
3. 人が採用したYAMLを、通常のプログラムで検証・解決してUI部品、スタイル、Skill、検査設定へ同時反映する。
4. AIがプロファイルのguidanceと機能の目的を読み、画面構成と操作経路を実装する。
5. 設定と生成物の一致、実操作、意味と見た目を別々に検証する。

## 維持する意味

共通化するのは特定の美学や全画面のレイアウトではなく、状態・操作・失敗・復旧の意味。必要な比較情報を維持し、色だけに依存しない。フォーカス、選択、無効、処理中を混同しない。部分障害では正常な領域と入力を保ち、欠損と影響を伝える。

実データのUndo、処理の取り消し、二重更新防止、安全に継続できる範囲は利用アプリが保証する。応答未取得を成功や失敗に決めつけない。年齢や役割のラベルだけから見た目を自動的に推定しない。

## 開発ツールと共通UIの範囲

単一リポジトリ、単一の非公開npmパッケージ、Angular/TypeScript、Tailwind v4、YAML設定、init/sync/check、プロファイル例、生成Skill、実ブラウザー検証。実行時のAI API、サーバー、DB、全画面YAML DSL、複数フレームワーク、UX総合点、npm公開は含めない。

共通UIの拡張範囲は、[ユーザーの依頼原文](ui-library-request.ja.md)にあるすべてのカテゴリ・制御項目と共通基盤。[要求マトリクス](ui-library-matrix.json)の181行で既存機能での充足・変更・新規実装・依存関係・検証を追跡する。Cardの全領域、再帰構造のMenu、終了を保留できるDialog、時間指定と表示保持ができるSnackbarだけで打ち切らず、編集表・階層・日程・媒体・専門部品と、フォーム・言語・日付書式・RTL・プロファイルへの接続まで含める。

部品名とprop名は既存設計に合わせるが機能を黙って減らさない。成熟した描画・編集・計算エンジンは公開APIを通して利用する。静的カタログ、名前だけの部品、汎用ラッパー、未実装のスタブを完成と数えない。画面へ配置する部品は利用者の目的で選ぶ。個別部品の組込みと、実際のバックエンドへの保存・送信・Undoの成功を分けて検証する。

設定の型と必須役割、生成物の所有範囲、具体的な受入条件は[設計](design.md)に置く。
