# Angular移行と導入体験の修正計画

基準は2026年11月20日の `cd97bbee`。同日のnpmでは `latest` と `beta` が `0.1.0-beta.4`、`next` が `0.1.0-beta.5` を指している。今回の候補 `0.1.0-beta.6` はアプリの `vendor/` に保存して検証する。新しい開発者が小さなフォームを作り、その表示・入力・復旧の契約を次の担当者がPRで確かめられることを目標にする。

## 今回の移行

AngularとCDKを22.2.1からnpmの安定版22.3.0へそろえる。コンパイラーのpeer範囲に入るTypeScript 6.0.3を使う。このリポジトリの配布単位はCLIと生成ソースで、アプリのビルドは利用先が所有する。変更は生成元へ入れ、生成先と同梱資料は `ui:sync` で更新する。

| 順序 | 変更 | 受入条件 |
| --- | --- | --- |
| 1 | Angular・CDK・compilerを同じ版に固定し、依存通知を更新する。公開済みの版と識別できるローカル候補を作る。 | クリーンな依存解決、strict AOT、CLIの生成一致、npm配布物からのビルドが通る。 |
| 2 | 画面はsignal input、算出値はcomputedに寄せる。仮想行の入力をsignalsへ移し、行キーとCDKの描画・購読をディレクティブで接続する。 | 同じ行キーのDOMと編集状態を保持する。空配列・並べ替え・スクロール・キーボード移動・破棄後の動作を確認する。 |
| 3 | PDFの読取状態をResource APIに集約する。ファイル読込、worker/sessionの解放、canvas描画をそれぞれ一か所で管理する。 | 取得中に文書を変更・消去した場合も、旧文書のページ数・文字・エラーが新しい画面へ戻らない。同じ文書の再試行、実workerの起動と破棄を確認する。 |
| 4 | テキスト入力の編集中の表示とフォームに通知する値を分ける。コピー結果を、開始時に表示していた内容に対応付ける。 | 日本語の変換確定、変換バッファの明示設定、resetを確認する。保留中にコピー対象が変われば古い結果を通知せず、次のコピーを実行できる。 |
| 5 | 基本フォームと翻訳のサンプルを軽量な公開入口から使えるようにする。アプリのCI例は本体CLIで生成一致と指定ソースを検査する。 | 専門エンジンをインストールしていない利用アプリで、配布した翻訳サンプルと入力欄がビルドできる。生成CSSを手編集するとCI用コマンドが失敗する。 |

### 設計の境界

行キー・選択・再試行条件などの規則は、Angularやブラウザーに依存しないTypeScriptで扱う。部品は入力・表示・操作イベントを所有し、読取の寿命は部品に結び付ける。PDF.js、CDK、クリップボードなどの外部APIとのやり取りは各機能のアダプターへ集める。保存・送信・Undoの永続化と結果確認は利用アプリが所有する。

`resource` は置き換え可能な読取に使う。利用者が起動したコピーや保存は明示的な操作として実行し、完了通知をその要求と照合する。Reactive FormsのControlValueAccessor、CDKのObservable契約、検索のdebounceを保持する。仮想行には `ngDoCheck` を残し、同一配列の要素差し替えや、Tab移動中に必要になる行をその場で描画する。タブ等の投影内容も従来どおり同期的に検査する。[設計判断](adr/0006-angular-state-and-io.md)・[AngularのResource API](https://angular.dev/guide/signals/resource)

## 更新と復旧

利用先ではCLI・lockfile・設定YAML・生成ディレクトリ・生成Skillを同じ変更として保存する。候補tarballで `sync --dry-run`、`sync`、`check --require-source-checks` を実行し、そのアプリのproduction buildと代表操作を試す。戻す場合はこの一組を同じ版へ復元して再検査する。レジストリへの公開と配布タグの変更は別のリリース作業とする。

### 導入見本の検証

Angular CLI 22.3.0で作成したアプリに候補をインストールし、`angular/forms` のテキスト欄、Reactive Forms、配布した翻訳アダプター、標準CSSを組み合わせた。地図・PDF・表計算のエンジンを追加せずに本番ビルドでき、初回に読み込むJavaScriptとCSSの合計は469.84 kB、推定転送量は96.90 kBだった。この構成で「東京」を入力し、Tabを押した後も値が残ることを確認した。各チームの初期サイズは、そのアプリのCIで同じ条件を固定して比較する。[導入手順](ui-library-consumer-guide.ja.md)

利用アプリのPRでは `npm ci` 後に `npx ui-foundation check --config ui.config.yaml --require-source-checks`、アプリの本番ビルド、下記の代表操作を実行する。ライブラリ側では `npm run test:package` が配布物のインストール、更新、復旧を、`npm run test:model` がモデルの依存方向を検証する。既存の静的警告には判断の根拠と再確認の条件を記録し、担当者の引き継ぎに使う。

### 更新後にチームで確かめる操作

- 一覧または表の2行目で入力中に並べ替える。編集行が離れた位置に移る場合や、同時に行高を変えた場合も、同じ入力欄にフォーカス・下書き・選択範囲が残り、続けて入力できることを確かめる。利用アプリが受け取る表示範囲にも移動先の行が含まれる。
- テキスト欄で「東京」を変換確定する。親フォームの値、入力欄、文字数が一致し、保存候補の通知が1回だけ届くことを確かめる。変換中にフォームをリセットした場合はリセット値が残る。
- PDFの読み込み中に別の文書を選ぶ。新しい文書だけが表示され、画面を離れれば旧workerが終了することを確かめる。
- コピー処理の完了前に下書きを変更する。古い処理が終わったときに新しい下書きの成功表示が出ず、現在の内容を改めてコピーできることを確かめる。
