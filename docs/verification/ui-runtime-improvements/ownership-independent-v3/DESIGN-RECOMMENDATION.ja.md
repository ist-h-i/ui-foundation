機械registryの最小契約

固定生成Skill scopeの予約JSON、例えば `.agents/skills/project-ui/ownership.json` を生成ownerのpointerにします。この場所なら既存output/Skill overlap禁止を再利用でき、`.ui`等の任意outputと新しい別rootmetadata scopeを衝突させません。内容はschema version、現在output、構築したmanifest_pathのような明示機械値だけです。必要ならconfig_pathも記録し、単一root内で別YAMLに切り替わる操作を既存ownerの勝手な移動としない契約を明示します。rootにつき固定Skill ownerは一つという制限は元からあります。

manifestVersionは1のままで、manifest.filesにregistryのSHAを追加します。registry内にmanifest自身のSHAを持たせると、manifest→registry SHA→manifest SHAの循環になるので避けます。pointerに対するownership根拠は、指した旧manifestの厳格構造・scopeと、そこに記録されたregistry SHA＝実registry bytesです。registryをJSON parseできること、内容が新expectedと同じこと、project-context内のoutputや文章、resolved.jsonの表示情報だけでは所有証拠にしません。新registryが既存unownedなら同内容でもrefuseします。

旧Version1 consumerのupgrade

同じoutputにある旧manifestは現行の構造・所有SHAで既存Skillを正当に確認できるため、通常syncでregistryをcreateし旧manifestをVersion1のまま更新できます。以後のoutput変更は固定pointerから旧output/manifestを決定できます。legacyの未upgrade consumerが最初からoutputを変更すると、旧場所を確実に特定する機械anchorはありません。project全scanやproject-context解釈を使わずこれを扱うには、`sync --from-output <old-output>`相当の明示migration入口が必要です。通常syncは何も変更せずその具体的な移行方法を診断します。消失registryからの移行も、現outputの有効manifestを使える場合は再生成でき、outputが既に変わっている場合は同じ明示旧pathが必要です。

--from-outputはsync専用にし、dry-runと併用可能、duplicate/missing値/絶対path/../.git/node_modules/Skill overlap/旧path symlinkはI/O変更前に拒否します。registryが示すactive ownerと明示fromが食い違う場合、複数ownerを勝手にunionしません。既存new target manifestやunowned fileを「同内容だから」「manifestがあるから」とadoptしません。manifest候補の曖昧さ、registryの破損/手編集/ownership hash不一致はfail closedとします。

migration planと書込保護

旧output、new output、固定Skillの全present＋旧manifest.filesを対象にして、旧owned files/Skillは旧SHA、未所有は拒否、欠損owned filesは許可という現契約を保ちます。旧manifestは指定された旧scopeでreadManifest相当を通したmetadataとして扱い、new manifestが既にある場合に現行:192の無条件skipへ入れてはいけません。旧outputへのunexpected fileやsymlinkも黙って残す/消すのではなくplan前に拒否します。targetが実際にはcase-fold同一や旧新のancestor関係の場合は、この最小版では明示errorを推奨します。対応するなら通常migrationと分けてunion/symlink/同一inode/削除対象の証明が必要です。拒否時に無変更を守り、非重複の中間output経由は可能な操作として記載できます。

planはnew owned files作成、固定Skill更新、旧owned files削除、old/new manifestの退役/作成とregistry pointer更新を全てcreate/update/deleteとしてdry-runへ出します。旧directoryのrecursive rmは使わず、列挙owned file＋正当に確認した旧manifestだけを削除します。app source/importはアプリ所有で変更しません。空directory整理はownershipとfile rollbackを壊さない範囲に限ります。

書込み前に全oldContentsを採取し、通常のatomicWriteとattempted逆順rollbackへregistry・両manifestも含めます。metadataは末尾へ明示順序付けし、target manifestとpointerのcommit、旧manifestの退役を曖昧にしません。途中のordinary EACCES/ENOENT等ではbytesと既存所有証拠を全復旧し、再試行で正常sync/check/二回目changes=[]に戻します。現docsどおり強制終了や同project同時書込みの全transaction原子性まで保証しません。必要なら別のlock/transaction課題として扱います。

checkはread-onlyでpointer/current config/current manifestの一致、registry byte、全expected output/Skillを確認し、移行前や旧版metadataはinvalid/upgrade要として表示します。自然言語からregistryを補完しません。generatedFiles/stableJSONは同入力・同版で同じregistry/manifest内容を返し、sync --dry-runはdirectory作成も書込も行いません。legacy bootstrapのcheckがMissing metadataを返す場合は、正当なsync upgradeを先にする説明を添えます。
