# Diagram 入力検証の契約

対象は PR11 の Diagram 2 件（空ラベルと負の配置）です。基準は `9f5430ca87e249af204cc335a8610d0d8040621f`。部品は引き続きアプリの `model` を表示し、有効な編集を `changeRequested` で要求します。データ更新、保存、Undo はアプリが担当します。

ノードラベルには、`String.trim()` で空にならない文字列が必要です。有効なラベルの前後の空白もアプリの原文として保持します。X/Y は有限の数値で、両端を含む `0..1000000` の範囲です。小数は使用できます。モデルの検証と `changeDiagram` の結果の検証でも同じ条件を適用します。

無効なフィールドの確定は変更要求を発行しません。ネイティブ入力の原文、アプリのモデル、キャンバスの有効な名称・位置、選択状態を保持し、理由を `role=alert` に表示します。対象入力には `aria-invalid` と、その理由への `aria-describedby` を付けます。訂正後の有効な確定では、そのフィールドの検証状態を解除します。フォーカスの移動はネイティブ入力と利用者の操作に従います。

プロファイル、辞書、無関係なモデル値の変更では入力の原文を保持します。辞書変更時はライブラリの検証文言を再表示し、アプリのノードラベルは翻訳しません。アプリが該当フィールドの値を実際に変更した場合、または対象ノードを除去した場合は、その値に対応する古い検証状態を解除します。同じ値を含むモデルへの置換を、入力のリセット命令として扱う契約は追加していません。

外部モデル自体が無効な場合は、理由と元のデータ表を表示し、無効なキャンバスの描画・編集を抑止します。元データの修復はアプリが行います。読取り専用・無効・処理中の既存ガードは継続します。矢印キーは配置を移動し、境界では `0..1000000` に収めます。既に境界にある場合の外向き移動は変更要求を発行しません。

見た目は既存のセマンティックトークンとプロファイルを使用します。新しい設定、依存、CSS、locale モジュール、公開 props は追加していません。必須・範囲制約と理由通知の設計は [WAI のフォーム検証ガイド](https://www.w3.org/WAI/tutorials/forms/validation/)を参照しました。
