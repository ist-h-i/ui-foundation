# UI静的検査の警告分類と取り込み

現在は最終検証・独立レビューの準備中。commit・push・通常mergeまでがユーザーから認可された範囲であり、完了結果は確認後に追記する。

## 分類

最新の通常CLIは200ファイル・10,313検査、違反0件・警告122件、既存の理由付き例外334件。ソースと診断は前段の固定結果と一致した。3担当による全件調査を主担当が照合し、警告は全件、具体的な理由がある未確認として残す。今回、新しい確定違反・安全に無条件解消できる解析候補・追加例外はない。

正本は[警告台帳](../../ui-warning-reviews.json)、全件の理由は[分類表](../../ui-warning-reviews.ja.md)。公開CSS上書き32、DOM/配置実測27、実行時寸法・構造入力20、外部engine11、仮想行/CDK10、検証用可変入力10、画像decode/非同期媒体8、印刷文書2、DOM復元1、関数差し替え1に分類した。

既知の有限分岐やguardがあっても、任意のCSS writer・入力・測定・callback順序全体を閉じたと認定しない。警告を例外で隠したり、Unknownを成功へ変えたりしていない。warningとerrorの従来の終了状態は維持する。

## 追加した受入チェック

`npm run ui:check:warnings`は本リポジトリの設定・生成一致・静的検査と分類台帳を照合する。未分類、消滅、重複、理由不足、根拠hash/anchorの変更は失敗。元のSourceReportは変更せず、warning台帳でerrorを承認できない。text/JSON出力を持ち、通常の`npm test`から実行する。

新しい回帰10件は、診断identityの各相違、Unknown維持、stale/duplicate、error/未設定、台帳不備、実ファイルのhash/anchor変化、欠損/symlink/path、CLI引数を確認する。初回は未実装のため失敗し、実装後のfocused実行が成功した。全体実行はこれから確認する。

## 試験資材の取り込み

巨大なローカル検証履歴を無差別にGitへ追加しない。静的回帰が必要とする9 JSONと2 raw reportを[固定fixture](../../../tests/fixtures/static-checks/README.md)へコピーした。4つのJSON内report pathと、3テスト内5つの読取りpathだけを変更し、元のreport bytes・producer/helper 45ファイルのhash・全例外のID/範囲/拒否assertionは維持した。移設後の関連6回帰は成功した。

過去のtrace・比較checkout・詳細snapshotは、このローカル検証ディレクトリ群と`output/`に保持する。過去記録の内容を変更・削除していない。今回の取り込みがclean checkoutだけで実行できることは、ステージするファイルを固定して別途確認する。

## 根拠を訂正した箇所

初版の調査資料では、layout 54参照とengine 34参照の説明用文字列を、実sourceの逐語anchorとして扱っていた。主担当の機械照合で不一致を検出し、担当が逐語文字列へ修正した。分類・元診断・保証範囲・ソースhashは変更していない。初版と不一致記録はローカルに保持した。最終の906参照は再照合し、台帳のチェックに通る形にした。

台帳組立て時のlayout担当の構造化した範囲記述も、厳格な検査が不正型として拒否した。内容とNOT_RUNを保持して文字列へ正規化し、検査側を緩和していない。

## 完成の範囲

指定したソースに対する静的逸脱の検出・単独配布・分類管理が対象。任意の実行時データフロー、全CSS cascade、未知renderer/外部engine内部、実利用の理解、視覚・アクセシビリティ全体の合格は含めない。有限回帰の結果と、この未保証範囲を分けて報告する。
