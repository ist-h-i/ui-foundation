# 0004: 仮想行のradio groupはアプリの完全な選択モデルへ接続する

日付: 2026-10-14。状態: 採用。[ADR 0003](0003-virtual-native-tab.md)のradio制限を、明示モデルを渡す構成について拡張する。検証はradio実行記録（開発元の参考資料: `../verification/ui-virtual-radio-20261014/README.md`。この生成Skillには含めない）。

## 背景

native radioのgroupは同じtree・form owner・非空nameで決まる。checked行が仮想DOMから消えると、残ったunchecked行が未選択groupの入口になる。最後に見たchecked値のキャッシュでは、描画外の外部更新、削除、並べ替え、reset、アプリによる変更拒否を観測できず、選択状態を二重に所有してしまう。

## 判断

VirtualListとVirtualDataTableへ任意のradioGroups入力を追加する。一groupの全memberの安定行key/native value、実効disabled/hidden、canonical valueをアプリが渡し、native changeで更新する。form省略はviewportの継承form owner、別formはidを明示する。native name/form/valueとモデルを一致させる。組込みsingle選択はselectedKeys/selectedKeysChangeへ同じadapterを内部接続する。動的radioGroupsと動的selectedKeysはreadonly Signal自体も受け付け、連続キーの局所renderで最新値を読む。配列bindingだけでは親のRAFベースの反映まで古いcanonical値が残る競合があるため、フレーム待機を要求しない構成ではSignalを渡す。

DataTableViewもselectedKeysのSignalを保持して子へ渡す。投影用virtualRadioGroupsは現在の検索・ページ適用後の行を完全に記述し、アプリが表示中の選択値またはnullを計算する。ページ外のcanonical選択はアプリに残す。

adapterは選択値を保存せず、描画済radioのcheckedとTab入口をcanonical valueへ同期する。未選択groupのフォーカス履歴はChromiumのUI状態として保持する。Firefoxは方向によらず先頭、WebKitは逆方向で末尾を入口にし、WebKitのhidden/disabled checked groupはTab対象外とする。同一行の複数optionはDOM順を使い、metadata配列順を要求しない。メンバー削除後は存在する行keyから準備先を導く。

Tab前に有限batchを探索し、描画外checked行がある場合も可視のunchecked peerを別のTab入口にしない。controlled構成のviewport入口は論理先頭、外部からの逆方向入口は論理末尾を準備する。外部focusを動かさず、既定のTabが次にこのviewportへ入る場合だけdocument handlerが準備する。通常のradioGroups未指定のスクロール再入場契約は維持する。

Arrow前には現在行と前後のeligible memberのdistinct行を最大3行用意し、nativeの左右方向・上下・wrap・input/changeを使う。TabやArrowを取り消してfocusを再実装しない。CDK内部も変更しない。元のtabindexは解除・破棄時に復元し、アプリが後から書き換えた属性を復元処理で上書きしない。フォームresetや拒否・遅延はアプリのcanonical modelへ従い、実操作後のrenderでcheckedを再適用する。

## 比較と帰結

checked行の無期限DOM保持や全行DOM化は、複数groupと外部更新の問題を解かず、描画上限も崩す。全行を走査して選択を記憶する方式もcanonical値と競合する。明示モデルはアプリ側の接続が必要だが、選択状態を一箇所で所有でき、失効したmember/valueを設定エラーとして扱える。

Tab入口の資格は標準APIで問い合わせられないため、実測したChromium／Firefox／WebKitの有限な内部方針を報告UAから選ぶ。Arrowの方向や端での折返しは各エンジンのnative動作へ委ね、checked memberが描画済みの場合とArrowの直前はpeerの元tabindexを保つ。無効な候補の全行DOM化は採用しない。UAの偽装・未知エンジンは既定のChromium方針へ戻り、成立を保証しない。

対象groupを一viewport内で完全に記述し、radioのtabindexは未指定または0にする。groupの外部member/別viewport共有、正のtabindex、shadow DOM/別document、モデルと異なるCSSだけの非表示・無効化は保証範囲外。macOS WebKitのradio操作検証は全controlへのkeyboard navigation条件を明示する。通常Tabがradioを対象外にするモード、SSR/hydration、未検証のブラウザ版・OS・実機・支援技術、極端な件数・高コスト投影は別途検証する。同期探索は最大データ件数に比例し、metadataも全member分を持つ。

## 再検討条件

group共有、制御しないnative checked状態の永続化、可変行高、別document、フォーム所有者の動的付替え、Angular/CDK更新を要求する場合に再評価する。有限Chromium試験から全構成の合格を推定しない。
